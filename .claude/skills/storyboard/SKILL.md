# Storyboard

The user is visual and not a film expert. They want to **see** every shot and approve it before anything is generated, so it does not end up as generic AI slop. Match the user's language in conversation and write shared documentation in English. Explain each technique in plain language through its visual effect and the feeling it creates.

**Hard rule: each phase ends with a STOP.** Show the result, ask for approval or changes, and wait. Never chain two phases in one turn. Never generate images or clips without an explicit OK that names how many will be generated.

## Setup

Run scripts from the project root with the venv on PATH:

```bash
export PATH="$PWD/.venv/Scripts:$PATH" PYTHONUTF8=1
SB=.claude/skills/storyboard/scripts
python $SB/melies.py search dolly zoom        # find techniques by name
python $SB/melies.py list lighting            # all techniques in a category
python $SB/melies.py shot camera-movement/whip-pan            # definition + preview media
python $SB/melies.py shot camera-movement/whip-pan --prompt   # + prompt_template (phase 5)
python scripts/videos.py learnings --tipo ia-storyboard             # past lessons, read before planning
python scripts/videos.py new "<name>" --tipo ia-storyboard --formato 9:16 --intencion "..."   # prints <id>
python $SB/storyboard.py init <id> --title "Title" --format 9:16
python $SB/storyboard.py build <id>           # writes 00_plan/storyboard.data.js + storyboard.html, prints URL
```

Categories: `camera-movement`, `framing`, `camera-angles`, `lighting`, `composition`, `lenses`, `color`, `time-and-motion`, `effects`, `editing`, `atmosphere`, `genre-looks`, `viral-looks`. The full index is 424 techniques; `melies.py index` prints it as JSON when you need to browse.

Each video lives locally in `videos/<YYYY-MM-DD>_<name>/` (created by `scripts/videos.py new`, see AGENTS.md). Shared lightweight examples belong in `examples/`:

```
00_plan/storyboard.json      source of truth (you edit this)
00_plan/storyboard.data.js   generated by build, do not edit
00_plan/storyboard.html      generated by build from templates/storyboard.html
01_referencias/              character / product / place reference images (phase 4)
02_keyframes/NN.png          phase 4
03_clips/NN.mp4              phase 5
04_audio/                    accepted music/voice and timing map (before animation); final SFX/mix
05_montaje/                  intermediate renders, HyperFrames project (phase 6)
final/                       deliverables: final.mp4 (+ cover image), retained after cleanup
```

`storyboard.json` format:

```jsonc
{
  "title": "…", "format": "9:16", "phase": 2, "version": 1,
  "idea": "Brief as understood, in 2-4 sentences.",
  "look": "Overall look: palette, light, texture, rhythm, references.",
  "notes": "Optional.",
  "shots": [
    {
      "technique": "camera-movement/crash-zoom-in",
      "description": "Concrete visual description: subject, location, action, framing.",
      "purpose": "Why this shot belongs here, in plain language.",
      "duration": 2.5,
      "transition": "Hard cut on the beat",
      "extra": "Optional additional lighting, colour, or lens technique.",
      "status": "propuesto",
      "alternatives": [{ "technique": "camera-movement/whip-pan", "why": "More energy, less impact" }],
      "keyframe": null, "clip": null      // later: "02_keyframes/01.png", "03_clips/01.mp4"
    }
  ]
}
```

For compatibility, stored `status` values remain `propuesto` (proposed), `aprobado` (approved), or `cambiar` (needs changes). `build` fills in each technique's name, link, reference clip and still; never write media URLs by hand.

**Showing the board:** serve it with `python -m http.server 8765 --bind 127.0.0.1 --directory videos` from the project root, or reuse a running local server. Open the URL printed by `build` (`http://localhost:8765/<id>/00_plan/storyboard.html`) with the browser available in the agent session. A local `.claude/launch.json` may define this server, but is optional and machine-specific. Also provide the local HTML file link. The board links Melies media from its site; never download or copy Melies clips, stills or text into the project.

## Phase 1 · Idea

1. Restate the subject, goal, audience, platform and aspect ratio (9:16 / 16:9 / 1:1), approximate duration, tone, and exclusions.
2. Ask at most 3 questions, only about what really changes the plan.
3. **Ask for the video's name** (suggest one short, descriptive name). It becomes the folder name.
4. Read past lessons (`videos.py learnings`) and apply what is relevant; mention it if one changes the plan.
5. Once the user confirms the idea and the name: `videos.py new` and `storyboard.py init`, then write `idea` (and a first `look` if it is already clear).

**STOP:** Confirm the interpretation and suggested production name with the user.

## Phase 2 · Shot proposal

Build the sequence in `storyboard.json` (`phase: 2`), check every ref with `melies.py shot`, run `build` and open the board. In chat, provide a short numbered list with each shot, technique, visual description, and purpose (one line per shot), plus one sentence describing the overall look.

Craft rules (this is where AI slop is avoided):
- **Hook in the first 2 s.** The first shot must be the strongest image or movement.
- **Rhythm:** about 2–4 s per shot; a 15–30 s piece is 5–9 shots. Vary duration so it breathes.
- **Vary scale and movement:** alternate wide / medium / close; do not chain two shots with the same camera move; static shots make moves hit harder.
- **Every movement is motivated:** it reveals, follows, or intensifies something. If a shot has no purpose you can state in one line, cut it.
- **One coherent look:** choose one color/film look (`color`, `genre-looks`) and one lighting approach (`lighting`) for the whole piece and put them in `look`. Use `extra` only for deliberate exceptions.
- **Transitions are part of the plan:** name each one (hard cut, match cut, whip pan, fade), using `editing` techniques when they carry meaning.
- **Avoid the generic AI reel:** no default epic drone + slow motion + lens flare everywhere, no shots that only exist because they look "cinematic".
- Give each shot 1–2 alternatives with a different feel, and say what changes (`why`).

**STOP:** Show the storyboard and its sequence playback. Ask whether the shots and their order fit, and whether the user wants changes or alternatives.

## Phase 3 · Storyboard review

Loop until the user approves the sequence:
- Apply each change in `storyboard.json`, bump `version`, rebuild, reopen, and summarize what changed in one or two lines.
- When the user requests another option, propose a genuinely different technique (another category or energy), not a near-synonym.
- Mark shots `aprobado` as the user confirms them.

Move to phase 4 only when the user says the whole sequence is approved.

### Preproduction audio (before animation and final timing)

Follow `GUIDE.md`, "Music before editing" and "Narrated video or interview".
Shot durations in the first storyboard are provisional. For music-led work, approve
an actual track and map its phrases, beats, energy changes and pauses before fixing
shot times or generating animated clips. For narration-led work, use the accepted
voice as the primary timing reference and select a supporting music bed.

Store the accepted audio, provenance/license, and timing notes in `04_audio/`.
Update shot durations/transitions in the storyboard, bump the version and rebuild.
Review the timed sequence with the user. Reference images/keyframes may be prepared
earlier, but the animation phase requires the accepted audio and timing map.

## Phase 4 · Keyframes

1. **Consistency first.** If a character, product or place repeats, generate one reference image for it, get it approved, and use it as the reference input for every keyframe that shows it.
2. Tell the user how many images you will generate and with which tool and model, and wait for the OK. Use the Higgsfield MCP (`generate_image`; `models_explore` to choose a model) or another image tool connected in the session.
3. Each keyframe prompt describes the **first frame** of the shot as the technique needs it: shot size, angle, lens feel, subject position, lighting and the global look, in the project's aspect ratio. A dolly in starts wide; a crash zoom starts on the wide context; a tilt up starts low.
4. Save reference images in `01_referencias/` and keyframes as `02_keyframes/NN.png` (two-digit shot number), set `keyframe` in the JSON, `phase: 4`, rebuild and reopen: each shot now shows reference next to keyframe.

**STOP:** Ask whether the keyframes match expectations and which, if any, need another take.

## Phase 5 · Animation

Before generating clips, confirm the preproduction audio and revised shot times exist.
Generate enough source duration for the approved cut and its transitions.

1. For each approved keyframe run `melies.py shot <ref> --prompt` and use `prompt_template` as the base: replace `[Subject]` with the real subject, add the shot's action, duration and look. Do not reuse `example_prompt`; it is Melies' own sample scene.
2. Load the `kling-ai` skill to adapt the prompt to the chosen video model (camera language, duration, motion strength, negative cues).
3. Tell the user how many clips, which model and the estimated cost, and wait for the OK. Generate image-to-video with the Higgsfield MCP (`generate_video`) from each keyframe.
4. Save as `03_clips/NN.mp4`, set `clip`, `phase: 5`, rebuild and reopen. The animatic now plays the real clips.

**STOP:** Show sequence playback with the real clips and ask whether any need to be regenerated.

## Phase 6 · Assembly

1. Use the accepted music/voice and timing map from preproduction; agree on the text on screen before building.
2. Simple cuts: concatenate with ffmpeg in shot order, trimming each clip to its planned duration. Designed transitions, titles or graphics: route through `/hyperframes` (`general-video`).
3. Add sound effects with `sound-effects` and finish placed-track mixing with `hyperframes-audio`; source any additional audio with `media-use` into `04_audio/`. Complete subtitles above overlays. Intermediate renders go in `05_montaje/`.
4. Render `final/final.mp4`, set `phase: 6`, rebuild.

**STOP:** show the final video and ask for last changes.

When the user is happy, close the loop in `videos.csv` (see CLAUDE.md): ask for a 1–10 rating, what worked and what to improve, and record them with `videos.py update <id> --estado terminado --nota N --duracion S --herramientas "…" --funciono "…" --mejorar "…"`. Add your own technical lessons (models that failed, prompts that worked) to those fields too. Offer cleaning (`videos.py clean`) but never run it without the user asking.
